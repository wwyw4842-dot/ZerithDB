cache, store and temporary directories. The existing task's dependency cache
was copied with APFS cloning before use; the source cache is not modified.
The frozen, offline CLI/config dependency installation succeeded and the lock
stayed byte-identical.

- Before changing the import, the original `pnpm --filter zerithdb-cli typecheck`
  exited 2 at `src/commands/init.ts(7,27)` with TS2835 (4.178 seconds).
- With the one-line fix, that same command exited 0 (0.554 seconds), and the
  original CLI build exited 0 (1.504 seconds).
- The actual `packages/cli/dist/cli.js` completed `--help` and
  `init zerith-cli-consumer-check --template blank --no-install`. Nine checks
  passed, including exactly four generated files, the package name and scripts,
  blank page, layout, ignore file, and absence of installed dependencies/locks.
  Raw command output and generated bytes/hashes are retained. The private
  temporary directory was removed after evidence capture.
- A deliberately absent bundle exited 1 at `built-entry`, with eight later
  checks explicitly unexecuted and zero CLI commands. It cannot become a
  zero-check success. This is a harness negative control, separate from the
  original compiler counterexample.

The smoke check runs the built artifact with a fresh HOME and working
directory, ignores stdin, and bounds each command at 20 seconds. The product's
existing DNS lookup of registry.npmjs.org is retained; it warns if offline.
No template dependencies, user project, credentials or customer data are used.
